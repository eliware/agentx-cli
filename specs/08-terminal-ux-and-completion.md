# Terminal UX and completion

Use Node readline promises. Keep one active REPL interface for the session; its completer must read the current cwd at completion time so `cd` updates completion without creating a second input listener. If the interface must be replaced after shell execution, interruption, setup, or recovery, preserve interactive command history outside the readline instance and restore it to the replacement interface. Up/Down history navigation, Home/End, and normal arrow-key line editing must work consistently before and after replacement. Completion examines the final whitespace-delimited token, lists entries in the token's directory, sorts locale-wise, hides dotfiles unless the needle starts with `.`, appends the platform separator to directories, and quotes names containing spaces. Return `[matches, token]`. Support POSIX and Windows path semantics.

Text wrapping must use terminal width with an 80-column fallback and preserve ANSI escape sequences sufficiently for readable output. User input prompts use light blue; assistant text remains white. Reasoning summaries use pale lime, with an initial `**header**` rendered underlined; per-turn usage uses yellow; the final cumulative usage report uses blue; web-search status uses purple; shell-call deltas use green; custom-tool deltas use orange; MCP tool deltas use cyan. Each streamed shell or custom tool call ends with a line break before the next streamed item. Assistant response deltas may contain inline ANSI SGR styling for richer terminal output, including colors, bold, dim, italic, underline, blink, and inverse. The renderer must append a full reset when delta streaming completes so styles cannot leak into later output; redirected output remains functional.

The live status controller tracks total elapsed time and reasoning/writing/executing phase durations. In one-shot/non-interactive mode, disable the refresh timer and print one status line for each state/progress change, followed by the final transaction summary. Render JSON-like fields such as `{"time":"1s","reasoning":"1s/1s",...}` in white with the active phase highlighted green. Refresh roughly every 250ms, clear temporary lines before streamed output, pause during tool output, and never erase final response text.

Resume, setup, rollback menus, and interactive shell interruption use shared raw-mode behavior where available, hide/show cursor, redraw framed content, support numbered choices, arrows, Enter, and Ctrl-C, and clean up listeners/raw mode on completion. Close the REPL readline interface while an interactive shell tool owns terminal input, then create a fresh interface before the next prompt so submitted lines are not echoed twice and readline history/navigation remains active. Interactive direct shell commands have no automatic timeout. While one is running, shell interruption uses a temporary raw data listener for Ctrl-C, terminates the command/process group, waits for completion, then restores readline and returns to the AgentX prompt without exiting AgentX. This Ctrl-C behavior is separate from Ctrl-T: Ctrl-T remains the agent/tool interruption used to time out an active model-requested `shell_call`; its tool result must explicitly say the user requested interruption, instruct the agent to stop executing or retrying commands, and return the current status to the user. Outside a running direct shell command, Ctrl-C retains normal AgentX exit/interruption behavior. Do not repeatedly install keypress parsers, so readline escape-sequence handling remains intact.

Usage reports show turns, input tokens, cached input tokens, output tokens, and calculated cost. Keep startup/status output concise; never dump complete tool results or encrypted reasoning.

If a response or tool continuation fails, the live status controller must be stopped and its temporary line cleared before rendering recovery menus. Failed requests must not leave a refresh timer writing over interactive prompts. Goal-mode interactive questions pause the live status timer and clear its temporary line before prompting; status resumes only after the prompt is answered.
